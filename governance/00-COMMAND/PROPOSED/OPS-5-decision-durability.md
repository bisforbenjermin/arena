# OPS-5 — Decision durability
Status: PROPOSED — not a ruling until the founder ratifies | Reversibility: REVERSIBLE | Undo cost: minutes (archive this file, remove one CLAUDE.md line) | Confidence: MEDIUM (no freeze has run under it yet) | Drafted: 2026-10-22

## Ruling
A ruling in `governance/10-CANON/DECISIONS/` is load-bearing from the moment it lands. Five rules keep it that way.

1. **Read before revisit.** No session spends high or max effort on a question until it has run `ls governance/10-CANON/DECISIONS/` and read any file whose title matches. If the question is ruled, there are exactly two legitimate outputs: build against the ruling, or a HANDOFF block proposing supersession. A fresh answer to a ruled question is drift, whoever produces it — chat, Code, or founder from memory.

2. **Change by supersession only.** OPS-2 (documents are superseded, never edited in place) already governs frozen specs; this extends it to rulings explicitly. A ruling changes only through a new file that names the ruling it supersedes, scores the alternatives, and states what changed or what the old ruling got wrong. The old file moves to `governance/90-ARCHIVE/<date>/` with `SUPERSEDED BY <id>` on its second line. Sharpening — narrowing without reversing, as OPS-1 was sharpened 2026-08-10 — is also a supersession; it is cheap, because the new file is the old one plus the narrower sentence. The only way a ruling is read is as written, so nothing is ever edited into it.

3. **Every ruling declares its weight.** The house header (`Reversibility | Undo cost | Confidence | Ratified by founder`) and a non-empty `## Downstream` section are mandatory. A ruling whose Downstream is empty is a ruling nothing depends on: it is flagged at the next A4 (the irreversibility review in `AUDIT_PROMPTS.md`) and either gains a dependent or is archived as advisory. Which effort tier reopens a ruling stays OPS-1's call (and OPS-4's, if ruled); this rule only guarantees the header exists so that call can be made from one line.

4. **Freeze gate.** Nothing is marked FROZEN — spec, contract, or artifact — until A4 has run against the freeze candidate and A1 (the coherence pass, rulings vs specs) is current, meaning it has run since the most recent ruling landed. The `_audit/` outputs are the evidence; their filenames go in the STATUS BLOCK that reports the freeze. `AUDIT_PROMPTS.md` already says "A4 before any freeze"; this makes it a gate rather than a habit.

5. **The canon stays legible.** `governance/10-CANON/DECISIONS/INDEX.md` lists every ruling with id, title, date, reversibility, confidence, ratification, status and a Downstream pointer, regenerated by `/index` (Sonnet) whenever a ruling lands or moves. The index is a pointer table, never a summary: one truth per fact lives in the ruling files.

### Build steps
1. In `CLAUDE.md`, under `## Rulings`, directly after the bullet that begins `- Never edit a ruling in place (OPS-2)`, add this one bullet, exactly:
   ```
   - A ruled question is read, not re-argued (OPS-5). Before any high- or max-effort work, run `ls governance/10-CANON/DECISIONS/`; if the question is ruled, build against it or hand off a supersession — never answer it fresh. Nothing is marked FROZEN without an A4 run against it and a current A1.
   ```
That is the whole build: one line, in the one file every Code session reads first. The guard keeps agents out of `governance/`, so nothing else is delegated.

### Done criteria
1. `grep -c "OPS-5" CLAUDE.md` prints 1.
2. After the pull request merges, the founder runs `/index` (so `INDEX.md` names OPS-5) and `/audit S2` (so every existing ruling's header has been checked once). Two commands, Sonnet tier.

## Why
- **Capture was fixed; durability wasn't.** "Rulings land immediately" stopped rulings from going missing — six weeks of architecture once did. Nothing yet protected a ruling after it landed. Re-litigation at session open is the most expensive drift there is: it spends max effort to rediscover a settled call, and the July ledger showed what three months of canon-versus-reality divergence costs.
- **Declared weight ends stalling.** The pattern named in A4 — over-weighting reversible decisions and stalling on them — comes from rulings that don't say how heavy they are. A header lets any session tell in one line whether a question deserves ten minutes or a max session.
- **Durability is the chosen longevity mechanism.** Four candidates were weighed on 2026-10-22: operator continuity, financial durability, decision durability, handoff-readiness. Decision durability was chosen because it is the one nobody else owns: financial durability already has CP-0 and GTM-2; operator continuity is the capsule's job; handoff-readiness waits until one venue is live. It extends the prime directive — optimise for resumption — because what a session resumes into has to hold still.
- **Proposals must not read like rulings** (OPS-4's lesson: PR-1 to PR-6 sat a month because a proposal read like a ruling). The ratification field on line 2 makes the difference visible before the Ruling section is reached.

## Alternatives considered
Scored 1–5.

| Option | Durability | Solo-operable | Upkeep (5 = low) | Total |
|---|---|---|---|---|
| Status quo — rulings land immediately; nothing protects them after | 2 | 5 | 5 | 12 |
| Full change control — every ruling change through a board sitting (OPS-4 on everything) | 5 | 2 | 2 | 9 |
| **Supersession-only changes + declared weight + freeze gate + index** | 5 | 4 | 4 | **13 ← chosen** |

Cost of the chosen option: one A4 run per freeze (one max-tier session), one A1 run whenever rulings have changed since the last, one `/index` run per ruling. First freeze under this ruling pays both A1 and A4, because six rulings landed on 2026-10-20.
Containment: only FREEZE events and ruled questions trigger anything. STATUS and NEXT movement never does; the OPS-1 boundary is unchanged.
